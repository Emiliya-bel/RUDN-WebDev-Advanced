# Design: Удаление карточки

## Контекст
Сейчас карточки создаются через `NewCardForm`, который использует `useMutation` из React Query и вызывает `createCard` из API. Сервер уже имеет готовый эндпоинт для удаления (`deleteCard` в `cards.service.ts`), но клиент его не использует.

## Принятые решения и альтернативы

### 1. Где разместить кнопку удаления?
**Решение:** Разместить кнопку (иконку корзины) внутри компонента `BoardCard`.
**Альтернатива:** Сделать отдельный компонент `DeleteButton` и передавать в него `cardId` через пропсы. Это избыточно для одной кнопки, поэтому оставляем внутри `BoardCard`.

### 2. Как подтверждать удаление?
**Решение:** Использовать встроенный `window.confirm()` перед вызовом мутации. Это просто, надежно и не требует создания дополнительных компонентов модальных окон.
**Альтернатива:** Создать кастомный модальный компонент. Это займет больше времени и не требуется по условиям тикета.

### 3. Как обновлять данные после удаления?
**Решение:** Использовать `invalidateQueries` из React Query (вызвать его в `onSuccess` мутации). Это заставит список карточек перезапроситься с сервера, и удаленная карточка исчезнет из интерфейса без перезагрузки страницы.
**Альтернатива:** Вручную обновлять локальный стейт (например, через `setQueryData`). Это быстрее, но может привести к рассинхронизации, если на сервере что-то пойдет не так. `invalidateQueries` — более надежный источник истины.

## Изменения в API
Добавить функцию `deleteCard(id: string)` в `client/src/api/cards.ts`, которая выполняет `fetch` с методом `DELETE` по адресу `/cards/${id}`.
